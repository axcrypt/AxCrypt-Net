# AxCrypt CLI Reference (`axcrypt`)

The `axcrypt` command-line utility provides AxCrypt file encryption from
the terminal on Windows, macOS, and Linux. It uses the same shared
`AxCrypt.Core` cryptography as AxCrypt applications, works fully offline, and
never logs passwords, keys, or plaintext.

## Commands

### `axcrypt encrypt`

Encrypt a file into the `.axx` format (AES-256, V2 format, compressed).

```
axcrypt encrypt --input <file> [--output <file.axx>] [--force]
                [--recipient-public-key <pub.json>]...
                [password options]
```

| Option | Meaning |
|---|---|
| `--input <file>` | File to encrypt (required) |
| `--output <file>` | Output file; default `<input>.axx` |
| `--recipient-public-key <file>` | Also encrypt to this recipient's public key (repeatable) |
| `--force` | Overwrite an existing output file |

The original file is not modified or deleted. The original file name and
timestamps are stored (encrypted) in the container and restored on
decryption.

### `axcrypt decrypt`

```
axcrypt decrypt --input <file.axx> [--output <file>] [--force]
                [--key-file <keypair.axx>] [password options]
```

| Option | Meaning |
|---|---|
| `--input <file.axx>` | Encrypted file (required) |
| `--output <file>` | Output path; default: the original file name stored in the container, in the input file's directory |
| `--key-file <keypair.axx>` | Decrypt using a private key pair generated by `axcrypt keygen` (the password then unlocks the key pair, not the file) |
| `--force` | Overwrite an existing output file |

### `axcrypt show` (alias: `info`)

Show metadata of an encrypted file without writing any plaintext to disk:
original file name, timestamps, and the recipients (key sharing) list.

```
axcrypt show --input <file.axx> [--key-file <keypair.axx>] [password options]
```

### `axcrypt keygen`

Generate an RSA key pair for key sharing.

```
axcrypt keygen --email <address> [--output <dir>] [--bits 4096] [--force]
               [password options]
```

Produces in `--output` (default: current directory):

- `<email>-keypair.axx` — the **private** key pair, encrypted with your
  password. Keep this file secret and back it up.
- `<email>-public.json` — the **public** key. Share this freely; others
  use it with `--recipient-public-key` / `recipients add`.

### `axcrypt recipients add`

Add one or more recipients (public keys) to an existing encrypted file.
Requires the file password. The file is re-encrypted in place; a
temporary plaintext file is created next to it during the operation and
is overwritten and deleted afterwards.

```
axcrypt recipients add --file <file.axx> --public-key <pub.json>... [password options]
```

### `axcrypt recipients list`

List the recipient e-mail addresses of an encrypted file.

```
axcrypt recipients list --file <file.axx> [password options]
```

### `axcrypt version` / `axcrypt help`

Print version/license information, or usage help.

## Secure password input

Password sources, in order of precedence:

1. `--password <pwd>` — **discouraged**: visible in shell history and
   process lists. The CLI prints a warning.
2. `--password-file <file>` — the first line of the file is used. Protect
   the file (`chmod 600` on POSIX systems).
3. `AXCRYPT_PASSWORD` environment variable — recommended for automation
   and CI; not visible in the process's command line.
4. Interactive hidden prompt (no echo) — recommended for interactive use.
   `encrypt` and `keygen` prompt twice for confirmation.

If stdin is redirected and no other source is given, the first line of
stdin is used, enabling `printf '%s\n' "$pwd" | axcrypt decrypt ...` from
secret managers.

## Exit codes

| Code | Meaning |
|---|---|
| 0 | Success |
| 1 | General error (I/O, permissions) |
| 2 | Usage error (bad/missing arguments, refusal to overwrite without `--force`) |
| 3 | Wrong password or wrong/unusable key |
| 4 | Input file not found |
| 5 | Invalid or corrupt file (not an `.axx` file, tampered, or truncated) |

## Automation examples

Nightly backup encryption (Linux/macOS cron):

```bash
#!/usr/bin/env bash
set -euo pipefail
export AXCRYPT_PASSWORD="$(secret-tool lookup service backup)"  # from a secret store
tar czf /tmp/backup.tgz ~/documents
axcrypt encrypt --input /tmp/backup.tgz --output /backups/backup-$(date +%F).tgz.axx --force
rm /tmp/backup.tgz
```

Windows PowerShell:

```powershell
$env:AXCRYPT_PASSWORD = Get-Secret -Name BackupPassword -AsPlainText
axcrypt encrypt --input C:\data\report.xlsx --output C:\vault\report.xlsx.axx --force
Remove-Item Env:AXCRYPT_PASSWORD
```

Scripted verification of a round trip:

```bash
axcrypt encrypt --input a.txt --output a.axx --force
axcrypt decrypt --input a.axx --output b.txt --force
cmp a.txt b.txt && echo "round trip OK"
```

Check for wrong password in scripts:

```bash
if ! axcrypt decrypt --input file.axx --output out.txt; then
  case $? in
    3) echo "wrong password" ;;
    5) echo "file corrupt" ;;
    *) echo "other failure" ;;
  esac
fi
```

## Settings and state

The CLI stores non-secret settings (e.g. calibrated key-wrap iteration
counts) in a per-user work folder; override the location with
`AXCRYPT_CLI_WORKFOLDER`. No passwords or keys are ever stored there.
